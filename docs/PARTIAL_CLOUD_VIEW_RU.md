# Частичная сетевая подгрузка фотографий

Реализация 0.1.9. Это отдельный путь просмотра; полное восстановление оригинала сохраняет прежний формат CVPOS3 и проверки байтов, дат и метаданных.

## Что передаётся

Зашифрованный JPEG нельзя декодировать по произвольному диапазону его исходных байтов. После полной проверки холодного оригинала приложение готовит пирамиду растровых фрагментов: уровни с шагом 1, 2, 4 и далее до одного обзорного фрагмента. Основной размер — 512 пикселей; добавлен один пиксель перекрытия для фильтрации на границах. EXIF-ориентация применяется в просмотрщике, координаты индекса относятся к исходному растру.

Фрагменты сохраняют результат нативного декодирования без дополнительной потери: пиксели ARGB/RGBA F16, альфа, цветовое пространство и, на Android 14+, пиксели и параметры Gainmap. Расширения Gainmap Android 16 также сохраняются. Данные сжимаются Deflate без потерь и шифруются AES-256-GCM отдельным ключом Android Keystore. Этот ключ не помещается в облачные файлы. Оригинальный контейнер остаётся самодостаточным по выбранной пользователем политике восстановления.

Фрагмент является производным представлением для экрана. Он не заменяет оригинал и не служит доказательством сохранности EXIF, встроенного видео, исходного кодирования и времён файла. Эти свойства подтверждаются только проверкой целого оригинала.

## Запись и возобновление

Независимые зашифрованные фрагменты объединяются в неизменяемые облачные пакеты до 32 МиБ, в папке `app:/ciel-vitrine-v2/tiles/`. Индекс хранит длину, смещение и SHA-256 каждого шифротекста, геометрию, исходные хеши, аккаунт и корень приложения. Индекс зашифрован отдельно и записывается атомарно.

1. Проверить принадлежность архива аккаунту и весь исходный оригинал по доверенной длине и SHA-256. Если местный источник недоступен, однократно восстановить оригинал для подготовки фрагментов. Это не происходит в пути зума.
2. Записать пакет на устройство, синхронизировать и сохранить индекс с намерением загрузки.
3. До PUT сохранить состояние «попытка начата». Существующие облачные объекты не перезаписываются.
4. Прочитать весь пакет обратно, проверить длину и SHA-256, идентификатор и версию до/после чтения.
5. При потере ответа повторять только чтение. Не отправлять неопределённую загрузку повторно.
6. Считать пирамиду готовой только после покрытия всех уровней и проверки каждого пакета. Ошибка подготовки не меняет статус проверенного холодного оригинала.

Неподтверждённый пакет, отсутствующий по ожидаемому пути, не получает автоматического повторного PUT. Может потребоваться отдельная сверка; исчезновение пути само по себе не доказывает удаление объекта.

## Чтение при просмотре

Первый кадр использует единственный обзорный фрагмент. Для текущего масштаба вычисляется уровень детализации и пересечение видимой области с сеткой. Запрашиваются только нужные фрагменты:

`Range: bytes=offset-end` с обязательным `206 Partial Content` и точным `Content-Range`.

Ответ `200` вместо диапазона, неверные границы/общая длина, обрыв и лишние байты отклоняются. HTTPS-переадресации ограничены проверенными доменами Яндекса; при смене хоста OAuth-заголовок удаляется, Range сохраняется. Перед/после группы новых диапазонов сверяется идентификатор и версия пакетов. Каждый диапазон проверяется по доверенному SHA-256 и AEAD с привязкой к исходному оригиналу и координатам. Только затем декодируются пиксели и Gainmap.

На устройстве остаётся ограниченный кэш шифротекстов. Повторное чтение проверяет хеш и AEAD. Неподготовленная пирамида или ошибка диапазона показывают ожидание/ошибку; скрытого скачивания целого фото в просмотрщике нет. Повреждённый фрагмент не становится изображением. При сбое детализации остаётся предыдущий кадр с сообщением и повтором.

## Ограничения и измерения

- Этот путь предназначен для статических изображений, которые нативный декодер Android умеет читать областями. Анимации и видео требуют другой организации данных; частичная подгрузка для них не заявлена.
- Предельный оригинал в текущем архиве — 128 МиБ. Пирамида ограничена 250 Мп, сторонами до 32768 и 2048 фрагментами. Несовместимый формат/цветовой профиль останавливает подготовку, сохраняя оригинал.
- Растровые производные без потерь могут занимать больше места, чем исходный JPEG/HEIF. Здесь нет обещания уменьшения общего облачного объёма или трафика каждого конкретного открытия относительно маленького оригинала.
- Подготовка идёт по пакетам; временные растры/пакеты ограничены бюджетом 384 МиБ, зашифрованный кэш — 128 МиБ, одна группа декодированных базовых растров — 96 МиБ. Есть резерв свободного места. Полное восстановление имеет собственный ограниченный кэш.
- Ключ и индекс фрагментов привязаны к установке. После их потери фрагменты необходимо заново построить из оригинала; это не новая гарантия восстановления всего каталога после переустановки.
- Яркость HDR зависит от возможностей экрана и нативного декодера. Проверка пикселей/Gainmap не доказывает физическую яркость экрана по SDR-скриншоту.
- Журнал измеряет подготовку/загрузку/проверку фрагментов, успешные полученные байты диапазонов, чтение кэша, декодирование, первый облачный кадр и детали после зума. Неудачные попытки учитываются. Последние восемь попыток сохраняются отдельно для каждого этапа, общие счётчики не отбрасываются. Вложенные времена не складываются. Отчёт не содержит имён, GPS, аккаунта, токенов или исходных путей.

Частичная подгрузка не даёт права удалить местный оригинал. Деструктивные действия остаются закрыты до отдельной реализации согласия Android, проверки последней копии и журнала удаления.
