# Проверка 0.1.9: просмотр оригиналов и частичная сетевая подгрузка

11 октября 2026 года. Этот выпуск добавляет настоящий путь чтения нужных участков статической фотографии из Яндекс Диска. Полное восстановление оригиналов остаётся отдельным путём CVPOS3; производные фрагменты не заменяют оригинал.

## Изменения

- Полноэкранное перелистывание соседних фото/видео. Вне текущей страницы декодирование, скачивание и воспроизведение не запускаются; при увеличении перелистывание отключается.
- Местные фотографии читаются из исходного файла, включая видимую область при зуме. Нативный Canvas сохраняет Gainmap; отдельные фрагменты сохраняют F16-пиксели, альфа-канал, цветовое пространство и параметры HDR. На Android 16 проверены дополнительные параметры Gainmap. Для форматов без нативного чтения областями остаётся ограниченный ImageDecoder fallback до 16 Мп, поэтому универсальное полноразмерное RAW-просмотрение не заявляется.
- Полноэкранный видеоплеер использует нативный SurfaceView и показывает воспроизведение/паузу и перемотку. Аппаратный HDR-путь предусмотрен, но физическая яркость HDR-видео на данном телефоне не измерялась. Тесты воспроизведения используют H.264, HEVC и AV1 без заявления поддержки любого профиля.
- Долгое нажатие включает выделение; выбранный набор можно отправить в холодный архив, добавить в избранное/альбом. Добавление в очередь заново проверяет привязки исходников. Удаление и освобождение места остаются недоступны.
- После проверки холодного оригинала готовятся независимо зашифрованные фрагменты. Все неизменяемые пакеты полностью проверяются обратным чтением перед состоянием «Фрагменты готовы». При просмотре выполняются только проверенные запросы Range; скрытого скачивания целого оригинала для зума нет. [Протокол и ограничения](PARTIAL_CLOUD_VIEW_RU.md).
- Журнал фиксирует реальные попытки, ошибки, сетевые байты, кэш и времена показа. Отчёт ограничен выбранными файлами. Последние восемь попыток хранятся для каждого этапа; общие счётчики не теряются. Подготовка отчёта вынесена из обработки каждого фрагмента.

Получен настоящий HTTP 206 с точным Content-Range. Сравнение объёмов относится к **производному пакету**, а не к размеру исходного JPEG. Растровая пирамида без потерь может быть больше исходного сжатого файла.

Контрольные времена: подготовка оригинала 74 035,87 мс; загрузка оригинала 15 839,00 мс; обратная проверка 6 303,06 мс; построение/загрузка/проверка фрагментов 57 103,26 мс; видимый диапазон 6 887,70 мс; повтор из кэша 2 706,79 мс. Подготовка включала проверку аккаунта и сетевое ожидание; это не время одного шифрования. Тест дополнительно проверяет аккаунт по сети перед каждой группой, включая кэш. Производственный просмотр проверяет аккаунт удалённо при открытии, а затем локально сверяет сессию. Эти числа не следует использовать как прогноз скорости пользовательской галереи; оптимизация экспорта журнала выполнена после этой контрольной проверки.

Использованы отдельные случайные объекты в облаке. Они оставлены в аккаунте: удаление облачных объектов ещё не реализовано. Личные снимки не удалялись, медиатека и сохранённый вход не сбрасывались. Незавершённая первая попытка при заблокированном телефоне не засчитана как успешная.

## Локальная проверка

- Сборка основного и тестового APK, **85 JVM-тестов**: 0 ошибок/неудач. Независимые Python-проверки POSv1 (4) и CVPOS2 (10) прошли. Lint: **0 ошибок, 41 предупреждение**; предупреждения включают обновления зависимостей, платформенный ExifInterface и выделение объектов при рисовании.
- Телефон Android test device, API 36: **27 тестов прошли**, 30,065 с. Запущены только `MediaSafetyAndroidTest`, `MediaContentAndroidTest`, `MediaTimelineAndroidTest`, `RecoverySelectionAndroidTest`, `GalleryViewerAndroidTest`, `TileTransportAndroidTest`, `PerformanceJournalAndroidTest`. Полный набор permission/session/inventory на личном телефоне не запускался.
- Изолированный эмулятор API 35: `OK (51 tests)`, 301,778 с; **48 прошли**, три проверки реального аккаунта пропущены без явного `real_cloud=true`. Полный набор запускался только на этом эмуляторе.
- Новые проверки транспорта отклоняют HTTP 200 вместо диапазона, неверные смещения/длины, обрыв, лишние байты, сжатое HTTP-тело, повреждённые шифротексты, изменение удалённой идентичности и повторную отправку неопределённого PUT. Проверены тёплый кэш, точные пиксели/цвет/HDR и журнал с 140 попытками без потери итогов и без включения чужих задач в экспорт.
- Во время разработки проверки обнаружили неопределённую EXIF-ориентацию PNG и неверный способ открытия локальных GIF/WebP через MediaStore-дескриптор. Оба случая исправлены; проверки телефона прошли с этими исправлениями. Прерванный запуск эмулятора с падением system_server не считается успешным.
- **0.1.9 / versionCode 10** установлена поверх прежней сборки на телефон. Подпись OAuth сохранена. Размер APK: **75 656 527 байт**; SHA-256: `BE1F824FDF24EF813319595F9EAB3FF564B9A660E1D13AA35F9814C5132462DF`. Файл: `artifacts/ciel-vitrine-0.1.9-debug.apk`.

Результат GitHub Actions добавляется после завершения. Незавершённые запуски не считаются успешными.

## Замер выбранных снимков

1. В ленте долгим нажатием выделить несколько статических фото и нажать «В облако». Для первого замера лучше использовать небольшой новый набор до 128 МиБ на файл.
2. На вкладке «Облако» дождаться проверки оригиналов и «Фрагменты готовы». Для прежних архивных записей нажать «Подготовить фрагменты».
3. Открыть именно «Облачную копию», увеличить и переместить область, затем повторить ту же область для проверки кэша. Открытие местного снимка измеряет другой путь.
4. Вернуться на вкладку «Облако». Карточка «Замеры ваших файлов» обновляет отчёт выбранного набора. Отдельно фиксируются шифрование, загрузка/обратная проверка, подготовка фрагментов, полученные диапазоны, первый кадр и зум; вложенные времена не складываются.

Личные оригиналы для этого замера удалять не требуется. Отчёт не содержит имён файлов, GPS, токенов, идентификатора аккаунта или исходных путей. Пользовательский замер пока не выполнен; контрольный тест выше его не заменяет.

## Границы результата

Частичная сетевая подгрузка реализована для статических изображений, поддерживаемых нативным декодером областей. Облачные анимации, частичное видео, автоматическое Live/Motion-pairing, multipart, восстановление каталога после переустановки, автоматическое самовосстановление и Android Trash/Free Up ещё не завершены. Видео из облака скачивается целиком в ограниченный проверенный кэш оригиналов.

Фрагменты и их ключ привязаны к установке; при их потере нужны повторное построение из оригинала и восстановление индекса. Проверки подтверждают конкретные условия и образцы, а не отсутствие потери при любых внешних сбоях. Ограничения системных дат остаются прежними: встроенные метаданные сохраняются в исходных байтах, наблюдаемая mtime восстанавливается там, где это позволяет назначение; неизвестная дата создания не выдумывается. Деструктивные действия не включены.
