# CVPOS2 — переносимый точный оригинал

Статус 0.1.2: одиночный потоковый контейнер, без multipart и случайного доступа. Не является разрешением на удаление источника. Формат реализован на стандартных AES-256-GCM и SHA-256; собственная криптография отсутствует. Стандартный алгоритм не заменяет аудит его применения.

## Политика восстановления

Ключ восстановления публичен и находится в заголовке вместе с полным неисполняемым описанием декодирования. Личный пароль, приложение, сервис разработчика и аккаунт не нужны для восстановления уже скачанного файла. Нужен совместимый декодер и его среда исполнения. Облако технически может прочитать исходник, EXIF и GPS. Приватный каталог и журнал используют отдельные секретные ключи.

Оригинал — точные прочитанные байты без пересжатия, изменения EXIF или декодирования формата медиа. Стандартный контейнер не гарантирует, что Android умеет показать любой RAW/HDR/кодек или распознать Live Photo. На этом этапе пользователь сохраняет отдельные файлы пары независимо; удаления нет.

## Раскладка

С версии приложения 0.1.4 новые облачные контейнеры и ручные экспорты имеют нейтральное расширение `.bin`. Формат распознаётся по первым байтам, поэтому прежние `.cv2` также читаются. В журнале каждой облачной задачи сохраняется вариант имени: старые операции продолжают обращаться к прежнему адресу `.cv2`, в том числе после неопределённой загрузки. Это соглашение об имени файла, а не новый криптоформат и не гарантия скрытия содержимого от провайдера.

Все двоичные числа — беззнаковые big-endian; значения вне безопасного диапазона реализации отклоняются.

| Область | Содержимое |
|---|---|
| Первые 8 байт | ASCII `CVPOS2`, затем CR LF |
| Следующие 4 | Длина JSON в байтах, 1…65536 |
| JSON | Строгий UTF-8, плоский объект ровно с десятью уникальными ключами |
| Каждая запись | 24-байтовый заголовок + ciphertext длины plaintext + 16-байтовый GCM tag |
| Последняя запись | Обязательный DONE, затем строгий EOF |

JSON: `format="CVPOS2"`, `version=2`, `cipher="AES-256-GCM"`, `key_hex` (32 байта/64 hex), `nonce_prefix_hex` (4 байта/8 hex), `bundle_id` (16 байт/32 hex), `chunk_bytes` (65536…1048576), `name` (до 1024 UTF-16 units), `mime` (до 256), `recipe` (полное описание раскладки и всех проверок внутри файла). Только version/chunk_bytes — целые числа; остальные — строки. Вложенность, массивы и повторные ключи запрещены. Метаданные не исполняются и не задают путь назначения.

H = SHA-256 **точных** первых 12 байт и JSON. Повторная сериализация JSON для вычисления H запрещена.

Заголовок записи: magic ASCII 4 (`DATA` или `DONE`), sequence uint64, original offset uint64, plaintext length uint32. sequence начинается с 0 без пропусков; offset — сумма длин предыдущих DATA. DATA имеет 1…chunk_bytes байт; только последняя DATA может быть короткой. Не более 4294967294 DATA. Пустой оригинал — ноль DATA и DONE.

AES nonce = nonce_prefix 4 + sequence 8 в big-endian. AAD = H 32 + точный заголовок записи 24. Ключ — key_hex, AES-256-GCM, tag 128 бит, без дополнительного padding/compression. Каждый tag проверяется до выдачи plaintext этого блока. Новый контейнер получает новый случайный ключ, nonce prefix и bundle ID. Повтор nonce под тем же ключом запрещён.

DONE получает следующий неиспользованный sequence, offset полной длины оригинала, plaintext length = 64. Его plaintext: SHA-256 оригинала 32 + SHA-256 префикса контейнера 32. Префикс включает всё до заголовка DONE, исключая DONE. GCM tag DONE, порядок, offset, оба хеша и EOF обязательны. Хеш всего физического объекта включает DONE и его tag; это отдельный digest.

Публичный ключ позволяет переписать внутренне согласованный контейнер. Для доверенной идентичности сравниваются отдельно сохранённые SHA-256 и длина оригинала; облачная очередь также сравнивает bundle ID и физический хеш/длину контейнера. Внешний злоумышленник или отказ облака не устраняются внутренними тегами. Частичный файл после ошибки не считается восстановленным.

## Независимые реализации

- Kotlin/JCA writer/reader: `pos-format/.../Pos2.kt`.
- Отдельный JVM/JCA decoder: `pos-reference-decoder`, без зависимостей от внутренних модулей приложения; нужен Java 17+. Собрать `:pos-reference-decoder:installDist`, запустить скрипт из `build/install/pos-reference-decoder/bin` с контейнером и **новым** путём назначения. Существующий файл не перезаписывается.
- Python reader/writer: `pos-reference-decoder/python/ciel_pos2_decoder.py`, нужен Python и установленный `requirements-recovery.txt`. При восстановлении создаётся новый файл; при ошибке удаляется только созданный этой попыткой результат. Подготовьте зависимости заранее, если восстановление нужно без сети.

Пример Python: `python ciel_pos2_decoder.py original.bin --output recovered-original.bin`. Входной файл `.cv2` также поддерживается.

Golden interoperability fixtures проверяют размеры 0, 1, 65536, 65537, 131079 байт, оба направления Kotlin↔Python, а также JVM-декодер. Это проверяет совместимость текущей версии; заморозка production-формата потребует дополнительных внешних fixtures, криптографического обзора, multipart и длительных fault-injection испытаний.
