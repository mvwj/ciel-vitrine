# Проверка сохранности и скорости — 0.1.7

10 октября 2026. Телефон Android test device, Android API 36; отдельный эмулятор Ciel_Vitrine_Test, API 35. Личные оригиналы не удалялись. Использовались созданные нами файлы и ранее закреплённые публичные JPEG. Реальные тесты добавляют собственные случайные контейнеры в Яндекс Диск, не перезаписывая существующие.

## Вывод и область проверки

Проверенные образцы восстанавливаются побайтно, вместе с встроенными EXIF/GPS/ICC и прочими данными файла. Проверка каждого результата сравнивает все байты, длину и SHA-256; внешняя mtime проверяется отдельно через нативный stat. Это подтверждение конкретных сценариев на двух устройствах, а не обещание сохранности при любых условиях.

В Android-приложении освобождение памяти, удаление оригиналов, облачная корзина и автоматический purge пока отключены. Консервативные правила удаления существуют в JVM-прототипе, но не подключены к Android-действиям. Прототип не является доказательством безопасности ещё не реализованной кнопки.

## Исправления, найденные проверкой

1. Восстановление раньше могло писать открытый оригинал до проверки завершающей записи контейнера. Теперь полный контейнер проверяется в приватном временном файле; только после проверки footer/EOF/тегов/хешей начинается запись результата. После записи результат читается целиком ещё раз. Повреждённый контейнер не затрагивает существующее назначение. Источник не удаляется.
2. Экспорт и восстановление отказываются перезаписывать непустое назначение. Совпадение URI, document ID и идентичности обычного файла по дескриптору проверяется до открытия с усечением. Отдельный тест обращается к одному inode через разные пути. Создание hard link запрещено SELinux на этих устройствах: проверка настоящего hard link здесь не заявляется.
3. Слишком длинные имя/MIME раньше молча обрезались. Теперь формат отклоняет такие значения до записи; Unicode-имя и MIME проверены без изменения.
4. Реальный облачный замер обнаружил округление mtime Java API: 127465457 ns превратились в 127465000 ns. Проверка не была ослаблена. Время теперь устанавливается по открытому дескриптору через futimens, синхронизируется и проверяется по тому же дескриптору. Исходные значения в контейнере не округляются. Новые фикстуры используют 987654321 ns. Нативная функция не меняет atime и отклоняет неподдерживаемый диапазон time_t; не выдаёт успех после переполнения. [Android Bionic](https://raw.githubusercontent.com/aosp-mirror/platform_bionic/master/libc/include/sys/stat.h) описывает futimens и UTIME_OMIT.
5. Миниатюра теперь обновляется при изменении поколения, времени или размера файла по прежнему URI. Просмотрщик не использует устаревший кеш оригинала. Ошибка декодирования/видео показывается явно, есть повторное открытие. Просмотр не переписывает оригинал.
6. Сетевые тесты на Linux использовали неоднозначный localhost после намеренного обрыва IPv4. Теперь тестовый URL содержит буквальный 127.0.0.1. Проверки обрыва и повторов сохранены. GitHub дополнительно запускает полный Android-набор на отдельном эмуляторе; реальное облако требует явного аргумента real_cloud=true и не вызывается CI.

Весь путь до проверенного облачного состояния (prepare + upload + verification) занимает 31,96–33,49 с. [Сырые результаты трёх опытов](fixtures/cloud-performance-0.1.7.json).

Монотонный таймер elapsedRealtimeNanos; три последовательных испытания одного созданного шумового JPEG 2048×1536. prepare включает упаковку и локальные проверки источника; upload включает account/folder/link и отправку; verification включает полное облачное чтение и сравнение; download включает получение ссылки/перенаправления и запись контейнера; restore включает дешифрование, повторное чтение и mtime; local decode — декодирование скачанного изображения.

Это время полной безопасной операции, не изолированная пропускная способность канала. Три опыта не определяют p95, скорость массовой загрузки, мобильную сеть или другие устройства. Прямое открытие облачного элемента из галереи пока не реализовано: download + restore + local decode измеряются отдельно и не называются временем готового облачного просмотрщика. Замеры не используются для отключения обратной проверки.

## Что ещё препятствует обещанию «ничего никогда не потеряется»

- Облачный каталог после переустановки, прямой облачный просмотр, автоматический поиск повреждений и самовосстановление рабочей копии ещё не готовы. Локальный паспорт и journal недостаточны для обещания полного восстановления новой установки.
- Избранное и члены местных альбомов в GalleryModel пока сохраняют URI без эпохи базы MediaStore. После сброса/перестроения базы прежний URI нельзя автоматически считать прежней фотографией. Требуется сохраняемая привязка к эпохе и собственному ID, миграция старых записей и тест переиспользования URI; текущая проверка обновления миниатюры этого не доказывает.
- Нужны реальные остановки процесса/перезапуски телефона на границах устойчивого журнала, нехватка места/EIO, отключение SD, изменения SAF/MediaStore, конкуренция, revoke и смена эпохи каталога. Нельзя подменять эти испытания 32 моделируемыми исключениями.
- После проверки временного файла окончательная запись в SAF не является атомарной транзакцией. Прерывание может оставить неполную новую копию или приватный временный файл. Оригинал/контейнер остаётся; результат не считается проверенным. Произвольному неисправному или враждебному провайдеру хранения нельзя приписывать универсальные гарантии.
- Современные пары Live/Motion Photo и sidecar нужно сохранять как целую группу; автоматическое обнаружение ещё не реализовано. Ресурс свыше 128 МиБ пока явно не поддерживается облачной очередью; multipart отсутствует.
- Внешние системные даты создания, добавления, atime/ctime, права и inode новой копии нельзя универсально воссоздать. Надёжно известные наблюдения сохраняются в контейнере; неизвестная birth time не выдумывается. EXIF/QuickTime-даты внутри файла сохраняются побайтно. При запрете или округлении mtime выбранной папкой приложение сообщает ограничение; это нельзя считать доказательством точного восстановления внешних дат.
- Пользователь выбрал самодостаточное восстановление без ключа. Ключ в контейнере публичен, поэтому провайдер технически может читать и переписать согласованный контейнер. Доверенная идентичность проверяется по отдельно захваченному паспорту. Один контейнер без независимого паспорта доказывает внутреннюю согласованность, а не защиту от намеренной подмены.
- Две зоны одного облака разделяют случайное изменение отдельных объектов, но общий аккаунт/провайдер остаётся одной точкой отказа. Внешнее удаление аккаунта или потерю обеих копий сервисом приложение предотвратить не может. Для этого нужен проверенный независимый экспорт вне этого аккаунта.

До подключения удаления нужны реальные Android-тесты восстановления каталога, устойчивого commit и конкуренции; свежая проверка всех компонентов группы; привязка паспорта к эпохе/версии источника; отдельная пользовательская область удаления; корзина 60 дней и отмена/восстановление. Истечение срока не должно само по себе разрешать удаление последней проверенной копии. Включение удаления — отдельный этап, не результат прохождения нынешних тестов.
