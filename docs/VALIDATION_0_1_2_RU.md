# Проверка 0.1.2 — CVPOS2 и выбранный холодный архив

8 октября 2026. Добавлены потоковый самодостаточный контейнер, независимое восстановление и Android-очередь выбранного файла в Яндекс Диск. Исходные файлы не удаляются. Реальный пользовательский аккаунт ещё не использовался для загрузки.

## Что проверено

- 63 JVM-теста прошли: основной safety-прототип, CVPOS2, независимый JVM-декодер, API-клиент и переходы холодного архива.
- Kotlin и независимый Python writer/reader совместимы в обоих направлениях на пяти граничных размерах: 0, 1, 65536, 65537, 131079. Python отдельно восстановил все десять Kotlin/Python fixtures; старые четыре POS v1 fixtures тоже проходят.
- Независимый JVM-декодер из собранного офлайн-пакета восстановил Python-контейнер на 131079 байт. Существующее назначение отклоняется, повреждённый результат не считается успешным.
- Повреждения ciphertext/метаданных/footer, усечение, дополнительные байты, неверный порядок/размер записи, большой bootstrap, несовпадающий доверенный хеш, изменившаяся длина источника и отсутствие прогресса чтения отклоняются.
- Потеря ответа после сохранения облачного объекта не приводит к повторному PUT. Повреждение облачной копии, отсутствие по пути и смена аккаунта сохраняют локальный staging и не выдают VERIFIED. Изменившаяся версия объекта во время readback также отклоняется.
- API-тесты проверяют создание папки, различие существующей папки/файла, запрет overwrite, точные байты одноразовой upload body, полное download body и OAuth на download. Transfer-запросы в этом тесте перехватываются локально; это не проверка настоящего сервера.
- APK собран, Android lint — без ошибок, 16 предупреждений (включая доступные новые версии зависимостей и существующие замечания интерфейса). Проверки не отключены.
- Девять Android instrumentation-тестов прошли на собственном AVD Ciel_Vitrine_Test, API 35: Android Keystore/AtomicFile, повторное открытие журнала, уникальные IV, подмена ID/повреждение ciphertext, настоящий ContentResolver roundtrip, защита URI aliases, fsync/rename staging, проверка изменения длины и сохранение источника. Другой запущенный AVD не изменялся.

## Границы этапа

Выбирается отдельный файл до 128 МиБ, одновременно до трёх незавершённых задач; сеть должна быть без тарификации. Без стабильного ID app-folder загрузка останавливается. Журнал хранится атомарно и зашифрован секретным Keystore-ключом; в WorkManager передаётся только случайный ID. Очередь восстанавливается после запуска приложения; Android может откладывать фоновые работы, а force-stop требует нового запуска.

Задача сохраняет UID/root, URI/grant, точные SHA-256/длины исходника и физического контейнера, bundle ID, ID/версию объекта и время проверки. Последняя проверка не доказывает будущую доступность файла. Исходник и холодные объекты никогда не удаляются; убирается только принадлежащий задаче временный локальный контейнер после сохранения VERIFIED.

Неопределённый PUT не повторяется автоматически. Выполняются до трёх попыток проверки, затем пользователь может повторить проверку. Если объект не наблюдается, задача остаётся неподтверждённой; внешнее переименование не считается удалением. Поиск объекта по ID и разрешение таких задач требуют следующего этапа. При создании новой отдельной задачи может остаться лишняя холодная копия; автоматической уборки облака нет.

Archive-all, multipart, Live Photo grouping, отдельная рабочая Gallery-копия, облачные превью/просмотр/скачивание через UI, облачное сканирование после переустановки, саморемонт, Android safety DB, Free Up и корзина ещё не реализованы. Снимок журнала выбранного файла не является ResourceSet proof и не разрешает удаление. Изменения источника той же длины, полная версия MediaStore и аппаратные power-loss испытания ещё не проверены для будущего удаления.

Первый реальный тест: вход в локальный APK, небольшой тестовый файл, завершённое полное readback и независимое восстановление скачанного CVPOS2. Затем нужны реальные revoke/401/403/404/429/507, обрывы, принудительная остановка и внешнее изменение объекта. Пароли и access token в чат не передаются.
