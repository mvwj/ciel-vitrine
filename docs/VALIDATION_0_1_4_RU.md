# Проверка 0.1.4 — нейтральное расширение контейнеров

9 октября 2026. Новые облачные оригиналы в обеих зонах и ручные экспорты получают расширение `.bin`. Это изменение имени файла: содержимое остаётся CVPOS2, алгоритм AES-256-GCM и выбранная политика восстановления сохраняются.

## Совместимость

В зашифрованном паспорте задачи сохраняется вариант расширения. При чтении старой записи без нового поля подразумевается `.cv2`. Поэтому уже существующая, подготовленная или неопределённо загруженная операция сохраняет прежний адрес. Новые задачи из SAF, MediaStore и создания Gallery Store явно выбирают `.bin`. Локальный внутренний staging сохраняет прежние имена `.cv2`; они не задают имя объекта в облаке.

Декодеры распознают формат по содержимому, а не по расширению. Старые `.cv2` и новые `.bin` поддерживаются одновременно. Архив с офлайн-декодерами и инструкции обновлены.

## Проверки

- 69 JVM-тестов прошли. Новая проверка читает старую запись без поля расширения и новую запись `.bin`, моделирует потерянный ответ после PUT и перезапуск. Обращения остаются по одному исходному адресу; повторного PUT нет.
- APK собран. Android lint: 0 ошибок, 18 предупреждений; проверки не отключены.
- Kotlin fixture на 131079 байт переименован в `.bin`. Независимые Python и JVM-декодеры восстановили файл; оба SHA-256 совпали с отдельным исходным fixture.
- APK установлен обновлением на подключённый телефон Android API 36, версия 0.1.4 подтверждена; запуск MainActivity завершился успешно. Медиатека телефона для автоматических тестов не использовалась.
- 17 Android instrumentation-проверок базовой логики выполнены в 0.1.3; в этом этапе повторно не запускались. Реальные upload/readback Яндекса по-прежнему ожидают проверки аккаунта.
