# Проверка 0.1.3 — массовая очередь и отдельные рабочие оригиналы

9 октября 2026. Программирование продолжается без подключения пользовательского аккаунта Яндекса. Этот этап добавляет очередь доступной медиатеки и создание рабочих контейнеров из проверенного холодного архива. Загрузка и проверка настоящего Яндекс Диска остаются отдельным испытанием.

## Реализовано

- Очередь готовится до входа. UID и стабильный ID папки приложения привязываются перед первым обращением загрузки; уже привязанная задача не переносится на другой аккаунт.
- Android SQLite: WAL и FULL, транзакционные страницы сканирования вместе с курсором, сравнение ревизии перед записью, зашифрованные паспорта/наборы/пакеты. AES-GCM AAD включает тип строки, ID и ревизию. Индекс источника защищён отдельным HMAC-ключом Keystore. В открытых индексах остаются случайные ID и служебные состояния; содержимое фото и организация не публикуются.
- Старый зашифрованный AtomicFile-журнал импортируется транзакционно и идемпотентно. Старые записи сохраняются. Утеря ключа существующей базы останавливает доступ, новый ключ поверх старых данных не создаётся.
- MediaStore сканируется по конкретным подключённым томам, по 120 файлов. Фиксируются эпоха базы, граница ID/поколения добавления, разрешённый доступ и позиция. Новые файлы после снимка войдут в следующий запуск. Изменение доступа/эпохи/носителя приостанавливает сканирование, отсутствие не считается удалением.
- Паспорт источника включает размер, размеры кадра, продолжительность, даты, том, media ID и поколение. Стандартный байтовый SHA-256 охватывает также цветовые профили, EXIF, дополнительные дорожки и неизвестные приложению данные; сравнение визуального качества не заменяет его.
- Для MediaStore требуется оригинальная версия с метаданными: `setRequireOriginal`, а на API 31+ также флаг EXTRA_ACCEPT_ORIGINAL_MEDIA_FORMAT. Доступ ACCESS_MEDIA_LOCATION запрашивается отдельно. SAF-провайдер без MediaStore отдаёт выбранную им версию; её нельзя автоматически называть камерным оригиналом.
- Источник полностью читается дважды; перед/между/после чтения перепроверяется паспорт. Контейнер fsync, rename и полный локальный readback предшествуют загрузке.
- Одна очередь загрузки с межпроцессной блокировкой, сохранёнными фазами, паузой и индивидуальным продолжением. Неопределённый PUT не отправляется повторно. Предварительная проверка аккаунта не превращает общую недоступность провайдера в ошибку каждого файла.
- Временное место ограничено 384 МиБ, плюс запас свободного места 64 МиБ. Резерв зависит от известного размера конкретного ресурса; уже существующий staging учитывается в лимите. Неподтверждённые контейнеры не удаляются ради продолжения очереди. Это ограничение staging, не размер всей базы. Рабочая перепаковка передаёт plaintext через ограниченную 128 КиБ pipe, без записи расшифрованного оригинала в отдельный файл.
- Все найденные большие файлы учитываются со статусом UNSUPPORTED_SIZE. Лимит загрузки остаётся 128 МиБ на ресурс; массовый список не выдаётся за завершённый архив.
- Пользователь вручную объявляет полный набор из 1–32 проверенных холодных ресурсов. Перед созданием Gallery Store целиком заново читается весь набор. Рабочие ресурсы получают новые CVPOS2, ключи, bundle ID, отдельную папку `gallery` и независимые object ID. Источник для рабочей копии — холодный контейнер, а не телефон.
- Интерфейс показывает счётчики, состояние сканирования, большие файлы, паузу/продолжение и страницы очереди по 30 записей. Выбор полного набора не является автоматическим распознаванием Live Photo.

## Проверки

- 68 JVM-тестов прошли, включая всю прежнюю safety-логику, отдельные физические рабочие объекты, полную проверку сопутствующего ресурса и передачу ошибки footer через pipe.
- 16 Android instrumentation-тестов прошли на собственном AVD Ciel_Vitrine_Test, API 35. В базе проверены 1440 записей, страницы и атомарный курсор, rollback устаревшего пакета, запрет устаревших записей, AEAD tamper/подмена ID, отсутствие ключа базы/индекса, импорт старого журнала и общий полный набор одного аккаунта.
- Реальный MediaStore: точное восстановление JPEG с GPS/EXIF, сохранение исходника, выявление изменённого паспорта и исключение файлов, добавленных после снимка списка. Рабочий контейнер на Android создаётся без доступа к телефону; испорченный footer холодной копии отклоняется и не заменяет уже проверенный staging.
- Через интерфейс без аккаунта собраны все 6 синтетических файлов тестового устройства. После паузы и принудительного завершения/повторного запуска очередь содержит те же 6 записей, пауза сохраняется, сканирование показывает COMPLETE. Это проверка собственной тестовой медиатеки, а не всей пользовательской библиотеки.
- APK и test APK собраны. Android lint: 0 ошибок, 18 предупреждений; проверки не отключены. Новые версии некоторых зависимостей требуют следующей версии SDK, обновление здесь не производилось.
- Независимые Python проверки четырёх старых POS v1 и десяти CVPOS2 fixtures прошли. Формат и офлайн-декодеры сохраняют совместимость с 0.1.2.

## Ограничения и следующий этап

Рабочие контейнеры ещё не связаны с облачным просмотрщиком, приватными превью и каталогом восстановления. Автоматическое распознавание Live/Motion Photo, multipart, импорт списка из облака после переустановки, симметричный ремонт двух зон, Free Up и 60-дневная корзина не включены. Ни список MediaStore, ни ручное объявление набора, ни прежнее время VERIFIED не разрешают удаление оригиналов.

Фоновые задания могут откладываться Android; после force-stop нужен запуск приложения. Повторный ручной сбор списка создаёт новый пакет и может создать дополнительные копии. Проверка исходника не удерживает вечную блокировку чужого файла: дальнейшая очистка потребует новой проверки после Android consent. Полноту произвольно меняющегося selected-access набора Android не гарантирует; список отражает доступные ресурсы во время прохода.

Нужно отдельно проверить реальные UID/root/transfer API Яндекса, revoke/401/403/404/429/507, обрывы и смену объекта. Аппаратная потеря питания и массовая библиотека 100 тысяч ресурсов пока не испытаны. Две зоны одного облака сохраняют общий риск провайдера/аккаунта.

Android API: [исходный медиаформат](https://developer.android.com/reference/android/provider/MediaStore#getOriginalMediaFormatFileDescriptor(android.content.Context,%20android.os.ParcelFileDescriptor)), [доступ к оригинальным метаданным](https://developer.android.com/training/data-storage/shared/media), [транскодирование](https://developer.android.com/media/platform/transcoding).

Для ручного составного набора ядро пока полностью проверяет все холодные ресурсы перед подготовкой каждого рабочего ресурса. Это консервативный прототип с дорогим сетевым readback; совместный снимок доказательств для всего набора и оптимизация трафика требуют следующего этапа.
