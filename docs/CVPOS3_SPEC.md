# CVPOS3 — точный оригинал с исходными датами

Версия 0.1.5. Байты медиа никогда не декодируются для повторного сохранения и не пересжимаются. EXIF, XMP, ICC, MakerNotes, GPS, встроенные даты и неизвестные приложению данные входят в исходный байтовый SHA-256. После восстановления проверяются весь оригинал и обязательный footer.

## Раскладка и совместимость

Раскладка записей, AES-256-GCM, nonce, AAD, DATA/DONE, хеши и границы прежние, как в [CVPOS2](CVPOS2_SPEC.md). Magic: восемь байт `CVPOS3` + CR LF. Затем uint32 длины JSON и JSON. `format="CVPOS3"`, `version=3`. Заголовок содержит прежние десять ключей и ровно пять дополнительных строковых ключей:

| Ключ | Значение |
|---|---|
| mtime_seconds | Знаковые секунды Unix, диапазон лет 1–9999 |
| mtime_nanos | Доли секунды, 0–999999999 |
| creation_millis | Достоверная дата создания источника, Unix ms, если известна |
| media_added_millis | Наблюдавшаяся дата добавления в MediaStore, Unix ms |
| media_taken_millis | Наблюдавшийся индекс даты съёмки MediaStore, Unix ms |

Пустая строка означает неизвестное значение. Числовые строки имеют каноническую десятичную запись без `+` и ведущих нулей. Пара mtime либо полностью известна, либо обе строки пусты. Три поля ms находятся в 0…253402300799999. Заголовок остаётся плоским; дубликаты и неизвестные поля запрещены. Весь точный заголовок входит в H и AAD каждой записи, а также в физический хеш контейнера.

Полное описание восстановления входит в каждый контейнер как `recipe`. Android, Kotlin, отдельный JVM и отдельный Python reader поддерживают версии 2 и 3; POS v1 также импортируется. Для новых файлов с датами нужен обновлённый офлайн-пакет 0.1.5. Старый decoder только версии 2 их не прочитает. Расширение остаётся `.bin`; старые пути облачных задач не изменяются.

## Значение дат

Даты источника не заменяются временем шифрования, загрузки, проверки или скачивания. Транспортные события имеют собственные времена. Gallery Store получает те же даты из проверенного холодного proof; телефон для перепаковки не нужен. Изменение исходника или его даты между чтениями не принимается.

На Android дата изменения снимается с фактически открытого оригинального дескриптора, с доступной нативной точностью. `ctime` не является временем создания и не используется вместо него. У Android нет надёжного публичного birth-time API в этом пути; `creation_millis` остаётся неизвестным. Дата создания/съёмки внутри EXIF сохраняется байт в байт независимо от этого поля. DATE_ADDED и DATE_TAKEN — наблюдения индекса, не новые определения времени создания.

После полного восстановления и повторного чтения известная mtime устанавливается на назначение и проверяется ещё раз нативным stat. Если провайдер назначения запретил установку или изменил точность, приложение сообщает об этом; исходные значения остаются в контейнере, восстановленные байты не выдаются за точное восстановление файловых дат. Android создаёт новую запись MediaStore и может назначить новые DATE_ADDED и inode/birth times. Универсального восстановления этих системных полей через SAF нет. Индексные даты не переписываются через read-only ContentValues.

Поля заголовка, включая эти наблюдения дат, открыты. Ключ восстановления также открыт по ранее выбранной политике; секретности от провайдера нет. Точность по доверенному паспорту требует совпадения физических хеша/длины контейнера и исходных данных, а не только внутренних GCM tags.

Основания: [MediaStore dates](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns), [SAF document metadata](https://developer.android.com/reference/android/provider/DocumentsContract.Document).
