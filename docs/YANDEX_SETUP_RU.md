# Подключение Яндекс OAuth

Первым выбран Яндекс Диск. OAuth-приложение пока не зарегистрировано. APK сохраняет выбор, но ещё не авторизует аккаунт. REST-клиент подготовлен; реальная проверка требует OAuth.

## Подготовленные данные

| Поле | Значение |
|---|---|
| Название | Небесная витрина / Ciel Vitrine |
| Android package name | `com.cielvitrine.app` |
| Тип для мобильного входа | Для авторизации пользователей, Android, LoginSDK |
| SHA-256 текущего debug-сертификата | `[LOCAL_SIGNING_CERTIFICATE_REMOVED]` |
| Google Play URL | Ещё не опубликовано; настоящий URL добавляется после публикации |

Отпечаток получен из местного debug.keystore и относится только к этой тестовой сборке. Для выпуска нужен отдельный сертификат. Client Secret не помещаем в APK.

## Регистрация

1. Откройте [создание приложения для авторизации](https://oauth.yandex.ru/client/new/id/) под вашим аккаунтом разработчика. Укажите название и свою контактную почту. [Официальная инструкция](https://yandex.ru/dev/id/doc/ru/register-auth).
2. Выберите Android, используйте package name и SHA-256 выше. Для мобильного OAuth Яндекс рекомендует [LoginSDK](https://yandex.ru/dev/id/doc/ru/mobileauthsdk/about).
3. Выберите доступ к Диску. Предпочтителен доступ только к папке приложения, если он позволяет подтвердить account/root binding. Конкретное разрешение и достаточность прав проверим при подключении, до запроса широкого доступа ко всем файлам. Телефон, дата рождения и портрет галерее не нужны.
4. Сохраните приложение. Для настройки нужен публичный **Client ID**. Его можно передать разработчику. Пароль, Client Secret и access token в чат/репозиторий не отправляйте.

Контактная почта и регистрация относятся к вашему аккаунту и сервису; вымышленные сведения не подставляем.

## После регистрации

Подключить LoginSDK, Keystore-хранилище токена, проверить идентичность аккаунта и корень приложения. В изолированной тестовой папке загрузить контейнер без overwrite, полностью прочитать обратно и независимо восстановить. Проверить revoke, 401/403/404/429/507, неизвестный успех и повтор. Только после этого включать пользовательскую очередь архива.

HTTP 202 означает, что загруженный файл ещё может не находиться на Диске; это не VERIFIED. Временные transfer URL и токены не попадают в логи. [Документация загрузки](https://yandex.com/dev/disk/api/reference/upload.html), [документация скачивания](https://yandex.com/dev/disk/api/reference/content.html).
