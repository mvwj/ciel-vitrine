## Регистрация

1. Откройте [создание приложения для авторизации](https://oauth.yandex.ru/client/new/id/) под вашим аккаунтом разработчика. Укажите название и свою контактную почту. [Официальная инструкция](https://yandex.ru/dev/id/doc/ru/register-auth).
2. Выберите Android, используйте package name и SHA-256 выше. Для мобильного OAuth Яндекс рекомендует [LoginSDK](https://yandex.ru/dev/id/doc/ru/mobileauthsdk/about).
3. Включите «Информация о Диске» (`cloud_api:disk.info`) и «Доступ к папке приложения на Диске» (`cloud_api:disk.app_folder`). Широкий доступ ко всем файлам, телефон, дата рождения и портрет галерее не нужны. Если права менялись после выдачи токена, повторите вход и проверьте разрешения. Приложение сообщает об отказах каждого read-only probe отдельно.
4. Сохраните приложение. Для настройки нужен публичный **Client ID**. Его можно передать разработчику. Пароль, Client Secret и access token в чат/репозиторий не отправляйте.

Контактная почта и регистрация относятся к вашему аккаунту и сервису; вымышленные сведения не подставляем.

## Проверка входа в APK 0.1.7

1. Установите локальную сборку `artifacts/ciel-vitrine-0.1.7-debug.apk`, откройте «Облако» → «Войти через Яндекс».
2. LoginSDK использует установленное приложение Яндекса или браузер. Разрешите доступ для галереи. Пароль и access token вводятся/выдаются в этом процессе, не в чате.
3. После возврата APK проверяет `/info` Яндекс ID (UID и Client ID), сведения о Диске и чтение `app:/`. Только после всех трёх ответов статус становится «Яндекс Диск подключён».
4. При повторном запуске сохранённый вход проверяется снова. Несовпадение UID или уже известного ID папки не заменяет старую привязку. Для смены аккаунта сначала используйте «Отключить на этом устройстве».

Токен записывается атомарно в AES-256-GCM envelope в `noBackupFilesDir`; ключ не экспортируется из Android Keystore. SDK logging выключен по умолчанию; токен не входит в Compose/StateFlow, галерейные prefs, SavedStateHandle, репозиторий или диагностические сообщения. «Отключить» удаляет только локальное подключение; оно не удаляет файлы и не отзывает разрешение OAuth на стороне Яндекса.

APK, собранный GitHub CI, подписан другим debug-сертификатом. Для проверки зарегистрированного отпечатка используйте локальный APK выше. Для релизной подписи потребуется отдельная регистрация сертификата.

Корень может не отдавать `resource_id`. Успешный вход не является доказательством сохранности оригиналов. В 0.1.2 выбранный холодный архив требует известный ID корня; без него очередь останавливается. Освобождение телефона и удаление отключены.

Документация: [LoginSDK](https://yandex.ru/dev/id/doc/ru/mobileauthsdk/android/3.1.3/sdk-android-use), [сведения об аккаунте с любым сервисным OAuth-токеном](https://yandex.ru/dev/id/doc/ru/user-information), [Android Keystore](https://developer.android.com/privacy-and-security/keystore).

## Проверка холодной копии

На вкладке «Облако» выберите один небольшой тестовый файл через «Сохранить файл в холодный архив». Требуется сеть без тарификации; лимит — 128 МиБ. С версии 0.1.4 приложение создаёт `app:/ciel-vitrine-v2/cold/<случайный ID>.bin`; старые задачи сохраняют адрес `.cv2`. Приложение не перезаписывает существующее и полностью скачивает результат для проверки. Статус «проверена» появляется после всех сравнений; исходник остаётся на телефоне. При неопределённом результате «Повторить проверку» не повторяет PUT. Локальный список операций переживает перезапуск, но пока не восстанавливается из облака после переустановки.

Реальный вход и двадцать точных восстановлений десяти публичных JPEG из двух облачных зон подтверждены на телефоне; результат испытаний загрузки/восстановления описан в [проверке 0.1.6](VALIDATION_0_1_6_RU.md). Для ручной проверки используйте небольшой тестовый файл. Также нужны revoke, 401/403/404/429/507, принудительные остановки на каждом шаге и независимое восстановление скачанного контейнера. Неопределённая операция без наблюдаемого объекта сохраняет исходник и остаётся неподтверждённой; новая попытка создаёт отдельный объект, возможный старый не удаляется.

HTTP 202 означает, что загруженный файл ещё может не находиться на Диске; это не VERIFIED. Временные transfer URL и токены не попадают в логи. [Документация загрузки](https://yandex.com/dev/disk/api/reference/upload.html), [документация скачивания](https://yandex.com/dev/disk/api/reference/content.html).

## Очередь 0.1.3 до входа

В 0.1.7 на реальном телефоне дополнительно выполнены три полных загрузки/скачивания собственного JPEG 3,19 МБ: исходные байты и точная mtime совпали. [Результаты и измерения](VALIDATION_0_1_7_RU.md). Для instrumentation реального облака теперь обязательно явное `-e real_cloud true`; в CI сетевые тесты аккаунта пропускаются. Обычный вход пользователя этого аргумента не требует.

На вкладке «Облако» можно заранее собрать доступную медиатеку или добавить отдельный документ. Сканирование не требует аккаунта и не удаляет файлы. Для точных MediaStore-оригиналов разрешите встроенные метаданные; после входа очередь требует сеть без тарификации и стабильный ID корня. Файлы свыше 128 МиБ видны отдельно и пока не загружаются.

Из проверенных холодных ресурсов можно вручную выбрать полный набор и создать рабочие копии в `app:/ciel-vitrine-v2/gallery`. Они получают другие контейнеры и object ID. Это подготовка Gallery Store; облачный просмотрщик, приватные превью, автоматическое pairing и очистка телефона ещё не подключены.
