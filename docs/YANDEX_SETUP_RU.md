# Настройка Яндекс Диска

Публичные исходники не содержат регистрации OAuth владельца проекта. Без
настройки приложение собирается и работает как локальная галерея; кнопка входа
объясняет, что требуется собственный Client ID.

## Регистрация

1. Создайте [OAuth-приложение](https://oauth.yandex.ru/client/new/id/) под своим
   аккаунтом. [Официальная инструкция](https://yandex.ru/dev/id/doc/ru/register-auth).
2. Выберите Android / LoginSDK. Package name: `com.cielvitrine.app`.
3. Получите SHA-256 **своего** сертификата подписи командой
   `./gradlew :app:signingReport` и укажите его в регистрации. Сборка CI, локальный
   debug APK и будущая релизная сборка могут иметь разные сертификаты.
4. Включите «Информация о Диске» (`cloud_api:disk.info`) и «Доступ к папке
   приложения на Диске» (`cloud_api:disk.app_folder`). Широкий доступ ко всем
   файлам и дополнительные персональные разрешения галерее не нужны.
5. Скопируйте `oauth.properties.example` в `oauth.properties` в корне проекта:

```properties
yandex.clientId=YOUR_PUBLIC_CLIENT_ID
```

Замените значение своим Client ID: 32 строчные шестнадцатеричные цифры.
`oauth.properties` игнорируется Git. Client Secret, пароль и access token туда
не помещаются и в Android не используются.

Альтернативы: переменная окружения `YANDEX_CLIENT_ID` либо Gradle property
`yandexClientId`. Приоритет: Gradle property → окружение → локальный файл.
Client ID не является секретом и попадает в настроенный APK, однако исходники
проекта не привязаны к регистрации конкретного владельца.

## Вход

Пересоберите APK, откройте «Облако» → «Войти через Яндекс» и подтвердите доступ.
LoginSDK использует приложение Яндекса или браузер. После изменения разрешений
в регистрации войдите повторно: старый токен не получает новые права автоматически.

После входа приложение проверяет аккаунт, сведения о Диске и папку приложения.
Несовпадение аккаунта или известного ID корня не заменяет сохранённую привязку.
Для смены аккаунта сначала отключите его на устройстве.

Токен хранится в приватном AES-GCM envelope с ключом Android Keystore. Он не
входит в UI-состояние, SavedStateHandle, логи или Git. «Отключить» удаляет
локальную сессию; файлы в облаке и разрешение на стороне Яндекса сохраняются.
Отзыв токена выполняется отдельно средствами Яндекса.

## Первая проверка

Используйте собственный синтетический тестовый файл и сеть без тарификации.
Выделите его и выберите «Загрузить и оставить на устройстве». Дождитесь проверки
холодного архива и рабочей копии. Успешный вход, HTTP 202 или завершение отправки
не являются доказательством сохранности оригинала — требуется полное обратное
чтение с проверкой байтов и метаданных.

Большие оригиналы используют multipart; лимит допуска 128 МиБ из старых версий
к ним не применяется. [Видео и большие файлы](VIDEO_AND_LARGE_ORIGINALS_RU.md).
Освобождение телефона имеет отдельную проверку и системное подтверждение:
[точные условия](CLOUD_STATUS_AND_LOCAL_RELEASE_RU.md).

Полный instrumentation-набор запускайте на отдельном эмуляторе. Для реальных
облачных тестов нужны тестовый аккаунт и явный аргумент `-e real_cloud true`.
Такие тесты оставляют собственные контейнеры в облаке и не запускаются в CI.
