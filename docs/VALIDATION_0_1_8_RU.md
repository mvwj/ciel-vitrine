# Проверка 0.1.8: оформление и безопасные привязки

10–11 октября 2026 года. Изменения продолжают аудит 0.1.7. Исторические замеры Яндекс Диска остаются в [отчёте 0.1.7](VALIDATION_0_1_7_RU.md); новых замеров облачной скорости в этом выпуске нет.

## Что изменилось

- Постоянная тёмная тема для галереи, альбомов, облака, настроек, карточек и диалогов. Фон запуска также тёмный; системные значки светлые. Между квадратными миниатюрами теперь 2 dp по горизонтали и вертикали. Это единица Android с учётом плотности экрана, а не два физических пикселя. Подписи дней, их увеличенные отступы, прокрутка по датам и виброотклик сохранены.
- Ручное восстановление полностью читает и проверяет контейнер **до** открытия диалога сохранения. Диалог получает исходные имя и конкретный MIME из CVPOS2/3. После выбора назначения контейнер снова проверяется; его полный SHA-256 должен совпасть с проверенным при выборе. Корректный, но заменённый другим корректным контейнер также отклоняется **до** записи назначения. Проверка всей расшифрованной копии и исходной mtime сохранена.
- Старый POSv1 не содержал имя/MIME: для него остаётся явно запасное имя `restored-original.bin` и `application/octet-stream`. Небезопасные имена с разделителями пути/управляющими символами и неподходящий MIME не передаются диалогу; метаданные внутри контейнера не переписываются. Пользователь и поставщик документов могут переименовать новый файл. Автоматическую индексацию произвольного SAF-назначения Android не гарантирует.
- Избранное и местные альбомы на Android 11+ используют URI конкретного тома, версию базы MediaStore и `GENERATION_ADDED` конкретной строки. Изменение содержимого не создаёт новую привязку; новая вставка строки или смена базы создаёт. Версия базы сверяется до и после чтения. Неподтверждённая привязка не добавляется в альбом.
- Миниатюры и просмотрщик сбрасывают прежнее состояние при смене привязки, даже если остальные поля совпали. После обновления медиатеки открытый снимок обновляет метаданные или закрывается, если привязка больше недоступна.
- Старые записи URI сохранены и автоматически не приписываются нынешнему снимку. В альбомах показано число доступных и неподтверждённых записей. Повторное добавление выбранного снимка подтверждает только его прежнюю ссылку. Перед первой записью новых привязок сохраняется копия прежних настроек; остальные ссылки не удаляются. Потеря доступа/отключение тома сохраняет членство. Ошибка чтения JSON альбомов блокирует его перезапись.

На Android 10 нет `GENERATION_ADDED`: просмотр медиатеки работает, но добавление избранного и членов альбомов блокируется с понятным сообщением. Одних URI, имени, размера и секундной даты недостаточно для уверенного различения новой строки. Это сознательное ограничение текущей реализации, а не обещание надёжности эвристики.

## Проверки

- Сборка основного APK и тестового APK, все 82 JVM-теста и независимые Python-проверки восстановления POSv1/CVPOS2 прошли. Lint: 0 ошибок, 25 предупреждений.
- Изолированный эмулятор Android API 35: `OK (40 tests)`, 66,502 с; два теста реального аккаунта пропущены без `real_cloud=true`, остальные 38 прошли. Полный набор запускался напрямую на явно указанном эмуляторе, без подключения личного телефона к набору permission/session/inventory.
- Телефон Android test device, API 36: повторный запуск четырёх безопасных классов `MediaSafetyAndroidTest`, `MediaContentAndroidTest`, `MediaTimelineAndroidTest`, `RecoverySelectionAndroidTest`: **17 тестов прошли**, 13,959 с. Использованы только собственные временные файлы/собственная тестовая строка MediaStore; доступ и облачная сессия пользователя не сбрасывались. Проверены точные байты и нативная mtime всех 14 образцов, просмотр и анимации, воспроизведение трёх видеокодеков, обновление привязки, зазоры/прокрутка и восстановление.
- Первый запуск на телефоне получил 5 ошибок UI из 17: аппарат заблокировался и Compose не получил экран. Он не засчитан как успешный; после разблокировки пользователем весь выбранный набор повторён успешно.
- Тёмная лента и узкие зазоры дополнительно просмотрены на экране эмулятора с собственными синтетическими файлами. Фон, подписи дней и нижняя навигация читаемы.
- Основная сборка **0.1.8 / versionCode 9** установлена поверх прежней на телефон. SHA-256 APK: `0B334107F1982086A5B1F62B6FE60D425757C429960013466BE719547FCB32DE`, размер 75391695 байт. Файл: `artifacts/ciel-vitrine-0.1.8-debug.apk`. Облачная регистрация и сертификат сохранены.

Оба задания GitHub Actions для исходного коммита `92ca36b` завершились успешно: [запуск 38085234095](private-historical-CI-run). `verify` проверил JVM/сборку/lint/независимое восстановление; `android-safety` на API 35 подтвердил 40 тестов, 0 ошибок, 0 неудач, 2 пропуска реального аккаунта (38 успешных). Суммарное время Android-тестов по XML: 96.862 с. Сырые отчёты сохранены локально в `artifacts/ci-safety-0.1.8-reports`. Последующее изменение отчётов не меняет код APK.

`RecoverySelectionAndroidTest` проверяет передачу подтверждённых Unicode-имени и MIME в настоящий контракт ACTION_CREATE_DOCUMENT, отмену результата, точные восстановленные байты, корректную замену архива между проверкой и записью, повреждённый footer, опасные имена и MIME. Контракт тестируется без взаимодействия с каждым возможным интерфейсом поставщика документов.

`MediaBindingAndroidTest` проверяет смену версии базы/переиспользование URI на моделируемых идентификаторах, настоящую строку MediaStore до и после изменения байтов, подтверждение одной прежней ссылки с сохранением остальных и резервной копии, а также запрет перезаписи повреждённого JSON. Настройки тестов находятся в отдельном случайном пространстве имён. Сброс базы личного телефона не выполняется.

Изменённый тест сетки измеряет зазор 2 dp и квадратность плиток, подписи и промежутки между днями. Тест прокрутки по-прежнему проверяет достижение старейшей даты за пределами 240 фото и виброотклик.

## Ограничения

Удаление оригиналов, автоматическое освобождение места и облачное удаление по-прежнему недоступны. Прямой облачный просмотр, восстановление каталога после переустановки, автоматическое самовосстановление, Live/Motion-пары и multipart остаются следующими этапами. Тесты этого выпуска не доказывают физическую устойчивость при выключении питания и исправность любого внешнего поставщика документов. Гарантии байтов, встроенных EXIF и наблюдаемой mtime и границы восстановления прочих системных дат описаны в предыдущем отчёте.
